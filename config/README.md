# Конфигурация: домены и URL сервисов

Иерархия переопределений (объявлена в шапке `.env.example`):

```
.env  >>  script  >>  config.default.json
```

Отображение переменных окружения на ключи конфига — `config/index.ts`, объект `envMapping`.

## Ключи, которые путают

| Ключ | Что это | Где берётся | Где используется |
|---|---|---|---|
| `mail:devBaseURL` / `mail:prodBaseURL` | **Транспорт**: адрес API почтового сервиса | `MAIL_BASE_DEV_URL` / `MAIL_BASE_PROD_URL` | `libs/axios.ts:5-7` |
| `mail:domain` | **Данные**: почтовый домен пользователей, часть адресов ящиков | `MAIL_DOMAIN`, дефолт `recompro.online` | адреса ящиков |
| `domain` | **Базовый URL приложения** для ссылок в письмах | `DOMAIN` | `models/user.ts:589,802,1003,1155,1415`, `models/system.ts:1241` |

Это три разные сущности. Транспорт может быть `localhost` или внутренним адресом
docker-сети, при этом почтовый домен пользователей не меняется.

## Почему `mail:domain` задаётся явно, а не выводится из base URL

Коммит `e483fe7ca` «divide mail config and mail url in config» убрал функцию
`extractDomain`, которая брала hostname из `MAIL_BASE_*_URL` и срезала префикс `mail.`
регуляркой `/^mail\./`.

Причины отказа от вывода:

1. **Вывод верен только при одном соглашении об именовании.** `mail-01.recompro.online`,
   `smtp.…`, `mx.…`, отдельный домен для почты или обращение по IP дают неверный домен.
   На невалидном URL `catch` возвращал `''`, и адреса ящиков собирались от пустого домена —
   ошибка тихая.
2. **Склеивались транспорт и данные.** Смена адреса API почты меняла почтовый домен
   пользователей.
3. **Спецкейс на localhost показывал, что связи нет.** Прежний код содержал ветку:
   если dev-URL содержит `localhost` — брать домен из prod-URL. Логика подпирала себя
   исключением.
4. **Ключ выпадал из иерархии переопределений.** Значение, вычисляемое в рантайме из другого
   ключа, нельзя переопределить, не подменив URL сервиса.
5. **Меньше императивной логики до старта приложения.** Ушли 22 строки с URL-парсингом,
   try/catch и ветвлением по `NODE_ENV`.

Слабое место явного значения: при переезде домена его можно забыть обновить, и рассинхрон
с `MAIL_BASE_*_URL` никто не поймает. Лечится проверкой на старте (`mail:domain` должен быть
суффиксом хоста из base URL — иначе warning или падение), а не возвратом к выводу.

## Открытые вопросы по `.env.example`

Не применено, ждёт решения.

**Строки 25-26 — дублирование.**

```
9   DOCTEMPLATE_API_PORT=3600
25  DOCTEMPLATE_BASE_DEV_URL=http://localhost:3600
26  DOCTEMPLATE_BASE_PROD_URL=http://localhost:3600
```

Порт уже задан строкой 9, а `config.default.json` держит те же `http://localhost:3600`
дефолтами. У Gotenberg аналогичных `BASE_*_URL` в примере нет — он работает от дефолтов.
Строки 25-26 предлагается убрать по аналогии.

## Решённое: `DOMAIN` (строка 37) остаётся

```
20  MAIL_BASE_DEV_URL=https://mail.recompro.online
21  MAIL_BASE_PROD_URL=https://mail.recompro.online
37  DOMAIN=http://localhost:3000
```

`DOMAIN` вынес в env коммит `e35c491b8` «Moved domain to env», убрав дефолт
`"domain": "http://localhost:3000"` из `config.default.json`.

На ревью поднимался вопрос, что `DOMAIN` дублирует строки 20-21 и его надо выводить оттуда.
Решение: **оставить как есть**. `domain` — базовый URL приложения для ссылок в письмах,
а `MAIL_BASE_*_URL` — адрес API почтового сервиса; это разные сущности, и выводить одну из
другой означает вернуть подход, от которого отказались в `e483fe7ca` (см. выше).
