# Протоколы тестов: v3 — ручная массовая рассылка

Проверка экрана «Рассылка документов» (`/account/newsletter/documents`) и массовых
операций над транзакциями:
пачки по 30, dry-run, отчёт, повтор неотправленных.

Заполняется по ходу прогона: в каждой таблице колонки **Факт** и **Итог** (OK / FAIL /
н/п — не проверялось).

---

## Подготовка стенда

| Шаг | Команда / действие |
|-----|--------------------|
| 1 | `npm run start:docker` — поднять `doctemplate` и `gotenberg` (оба должны быть `healthy`) |
| 2 | `npm run dev` — сборка и сервер |
| 3 | `npm run test:newsletter -- v3` — сид тестовых данных |
| 4 | Войти пользователем-владельцем тестовых аккаунтов (тот, у кого есть основной ящик — сид печатает его в строке `users: отправитель ...`) |

Письма по умолчанию уходят на собственный основной ящик тестировщика. Чтобы отправлять
на другой адрес: `NL_TEST_RECIPIENT=box@example.com npm run test:newsletter -- v3`.

Сид создаёт три аккаунта, все с префиксом `[NL-TEST]`:

| Аккаунт | Транзакций | Что моделирует |
|---------|-----------|----------------|
| `[NL-TEST] v3 массовая (35)` | 35 | выборка больше пачки в 30 |
| `[NL-TEST] v3 второй аккаунт (5)` | 5 | вторая группа для мультиаккаунтных проверок |
| `[NL-TEST] v3 без получателей (3)` | 3 | staff с `is_official_email = 0` → рассылка пропускается |

Аккаунта «без основного ящика» на этом экране нет намеренно: геттер транзакций
сужает выборку до `user_id = <читатель>`, поэтому чужой аккаунт в списке не появится
независимо от карты доступа. Этот сценарий проверяется только ночным пайплайном
(`npm run test:newsletter`). Ошибки отправки здесь моделируются остановкой gotenberg —
см. П-6.5.

Убрать данные после прогона: `npm run test:newsletter -- clean`.

> `npm run test:newsletter` без аргументов (полный цикл счётчиков авто-рассылки)
> удаляет все аккаунты `[NL-TEST]` — то есть и данные v3. Гонять их одновременно нельзя.

## П-1. Автотесты батч-рассылки

Запуск: `npm run test:newsletter:batch` (без БД и почтовика, ~20 секунд).

| № | Проверка | Ожидаемо | Факт | Итог |
|---|----------|----------|------|------|
| 1.1 | Группировка и загрузы | `OK: группировка по user_id:account_id, один загруз ящиков и staff на батч` | | |
| 1.2 | Частичный отказ | `OK: сбой сборки одного документа не роняет письмо группы` | | |
| 1.3 | Dry-run | `OK: dry run возвращает план писем и ничего не отправляет` | | |
| 1.4 | Код возврата | `echo $?` → `0` | | |

В выводе 1.2 присутствует красный лог `failed to build attachment for transaction 2` —
это ожидаемая часть сценария, а не ошибка прогона.

## П-5. Проверка рассылки без отправки (dry-run)

| № | Шаг | Ожидаемо | Факт | Итог |
|---|-----|----------|------|------|
| 5.1 | Выделить все 35 строк аккаунта `v3 массовая` → ПКМ → «Проверить рассылку (без отправки)» | Тост: «Уйдёт писем: 2 (транзакций 35). Получатели: <адрес>» | | |
| 5.2 | Вкладка Network | Два POST `/transaction-newsletter` с `dry_run: true` и пустым `files`; ответ приходит быстро, документы не формируются | | |
| 5.3 | Проверить почту получателя | Новых писем нет | | |
| 5.4 | Выделить 3 строки аккаунта `v3 без получателей` → проверка | «Уйдёт писем: 0 ... Групп без отправителя или получателей: 1» | | |
| 5.5 | Выделить строки двух рабочих аккаунтов сразу (5 + 5) | «Уйдёт писем: 2», в получателях адреса обоих аккаунтов | | |

Письмо в плане одно на пару «пользователь + аккаунт» внутри пачки, поэтому 35 транзакций
одного аккаунта дают два письма (30 + 5), а не 35 и не одно.

## П-6. Массовая авто-отправка пачками

| № | Шаг | Ожидаемо | Факт | Итог |
|---|-----|----------|------|------|
| 6.1 | Выделить все 35 строк аккаунта `v3 массовая` → ПКМ → «Отправить автоматически» → тип документа | Тост о начале, пункт меню переходит в «(выполняется...)» | | |
| 6.2 | Вкладка Network | Ровно два POST `/transaction-newsletter`: 30 транзакций и 5 | | |
| 6.3 | Дождаться завершения | Тост «Авто-отправка завершена: отправлено 35, ошибок 0, пропущено 0» | | |
| 6.4 | Почта получателя | Пришло 2 письма (по одному на пачку), вложений 30 и 5 | | |
| 6.5 | `docker stop project87-gotenberg-1`, выделить 5 строк второго аккаунта → авто-отправка | Тост «отправлено 0, ошибок 5»; письмо не уходит; после проверки `docker start project87-gotenberg-1` | | |
| 6.6 | Выделить 3 строки аккаунта `v3 без получателей` → авто-отправка | Тост «отправлено 0, ... пропущено 3» | | |
| 6.7 | Выделить строки двух аккаунтов сразу → авто-отправка | Запретов нет, отправка идёт по каждому аккаунту отдельно, итоги суммируются | | |
| 6.8 | Во время отправки кликнуть пункт ещё раз | Тост «Отправка ещё выполняется, дождитесь завершения», повторных запросов нет | | |

## П-7. Отчёт массовой операции

Выполняется сразу после П-6, не перезагружая страницу.

| № | Шаг | Ожидаемо | Факт | Итог |
|---|-----|----------|------|------|
| 7.1 | ПКМ по строке | В меню появился пункт «Скачать отчёт рассылки» | | |
| 7.2 | Нажать его | Скачивается `Отчет рассылки (N).csv` | | |
| 7.3 | Открыть в Excel | Кириллица читается, три колонки: `id;название;статус` | | |
| 7.4 | Сверить строки | Число строк равно числу транзакций последнего прогона, статусы совпадают с тостом | | |
| 7.5 | Прогнать отправку по аккаунту `v3 без получателей` и скачать отчёт | В колонке статуса «пропущено» | | |
| 7.6 | Перезагрузить страницу | Пункт отчёта пропал — результат последнего прогона живёт только в текущей сессии | | |

## П-8. Повтор неотправленных

| 8.6 | Уйти на другую страницу списка и нажать повтор | Тост «Неотправленных транзакций нет на текущей странице» | | |
